# 逐知识点核对来源

从[项目状态](../../STATE.md)确认本章允许的材料、版本和原笔记，从最终稿目录取得真实标题、序号及锚点。第 17 章使用[来源台账](../../sources/chapter17.md)中列明的两本用户 PDF 和三篇旧笔记。以实际文件核实版本，不把另一版的章节号套进当前版本。

## 怎样核对一条

1. 从本点挑出需要支撑的**具体结论**，打开原文上下文，核对版本、前提和所用示例。同一点的不同主张来自不同资料时，分别注明各自支撑哪一句。
2. 书籍记到能复查的最小单位，包括实际小节号和标题、条款或清单号、页码。写清采用 PDF 阅读器从 1 起算的页码还是书上印刷页码。旧笔记给仓库相对链接、原知识点编号和标题，注明原样保留、仅参考、概念沿用或经批准调整。
3. 区分原著结论和作者原例、用户批注、Agent 综合整理或简化示例。可以用自拟示例说明书里的规则，在来源栏分别写明规则依据和示例作者。标注“正文已读取”“仅目录或导览定位”或“待核对”及缺口。事后重新查到的依据标作“本次回溯核对”；历史上实际采用过哪些材料，以可追踪的记录为准。

## 同一次交付留下两份记录

先按知识点锚点更新内部台账，再根据刚核对的条目写聊天报告。**两处都要看得见每个交付知识点及其具体出处、用途和核对状态。** 整篇交付覆盖整篇，局部返修列出本轮受影响的点。用户要求的书本篇未使用时，注明“本篇未使用”。已有历史来源未知时保留“待核对”，写清本次能证明的部分。

对照当轮文稿和两份记录，逐一核对标题、页码含义、来源身份及覆盖范围。正式学习笔记沿用原有模板；详细来源对照由内部台账和聊天报告承载。核查后发现真实分歧，保留双方原文位置，链接到[问题账本](../../AUDIT.md)。
