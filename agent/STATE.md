## 已确认的协作约定

- 第 17 章围绕 C++11/14/17 面试主干，每轮按用户阅读速度推进一篇或一处修改。用户要讨论、解释或看草稿时在聊天交付，获准写入后再改对应范围。示例可由 Agent 核查，用户无需做编程练习。
- 新知识限于用户提供的两份 PDF 及三篇原始旧笔记。PDF 文件名、版本辨别和页码口径在[来源对照](sources/chapter17.md)维护。三篇原始材料分别是[线程基础](../Chapter17_concurrency_parallelism/note_17_1_thread_basics.md)、[同步原语](../Chapter17_concurrency_parallelism/note_17_2_synchronization_primitives.md)和[原子操作与内存模型](../Chapter17_concurrency_parallelism/note_17_3_atomic_and_memory_model.md)。
- **每个知识点的来源写两份**，一份在聊天里供用户逐点检查，一份在 `agent/` 里供交接。按实际采纳、原文已读、仅目录定位及教学改编作区分。历史材料不足就标待确认。正式笔记正文专注讲解。
- 修改旧知识点的标题、编号、位置、正文、代码、表格或图片前，按篇列出原文、拟改和理由并申请批准。用户自己修改过的段落以当前工作树为准。发现问题先登记；记录问题不会授予修改权限。
- 每篇交付时在聊天报告本次改动、逐点材料、逐项验收和待申请修改。验收分为通过、待确认、未完成，分别核查主题覆盖、技术准确性、原文保护、格式链接和来源追溯。
