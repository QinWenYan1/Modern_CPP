<a id="id1"></a>
## ✅ 知识点1: C++11 之前的并发编程困境

**C++11 之前标准库没有线程概念，并发代码只能依赖平台特定 API，难以跨平台移植。**

- 在 C++11 之前，C++ 标准库**根本没有线程的概念**
- 要编写并发代码，只能依赖**平台特定的 API**：
  - POSIX 的 `pthread`
  - Windows 线程 API
- 这让代码**难以跨平台移植**
- **C++11 首次把线程纳入语言标准**，使同一份并发代码得以**跨平台构建**

**注意点**
> 📋 **术语提醒**：线程(thread) 是操作系统调度的最小执行单元；`pthread` 即 POSIX thread，是 Unix/Linux 平台的线程接口标准
> 🔄 **知识关联**：「一份代码、处处构建」的跨平台思想与第 18 章 CMake 的设计理念一致——标准化消除平台差异

<a id="id2"></a>
## ✅ 知识点2: std::thread：创建执行的线程实例

**`std::thread` 用于创建一个执行的线程实例，是一切并发编程的基础。**

- `std::thread` 用于**创建一个执行的线程实例**，所以它是**一切并发编程的基础**
- 使用时需要包含 **`<thread>` 头文件**
- 构造时传入一个**可调用目标**（如 lambda 表达式）作为线程要执行的任务
- 它提供了很多基本的线程操作（见知识点3）

**注意点**
> 💡 **理解技巧**：把创建 `std::thread` 想成「执行流的分叉」——主线程分出一个新执行流，之后两路各自并发推进
> ⚠️ **关键区分**：创建线程对象 ≠ 等待线程结束——启动后两线程独立推进，需显式汇合（见 `join()`）

<a id="id3"></a>
## ✅ 知识点3: 基本线程操作 get_id() 与 join()

**`get_id()` 获取线程标识，`join()` 阻塞等待线程结束、与之汇合。**

- **`get_id()`**：获取所创建线程的**线程 ID**
- **`join()`**：**等待一个线程结束**（与该线程**汇合**）——当前线程阻塞，直到目标线程执行完毕才继续

**注意点**
> 📋 **术语提醒**：汇合(join) 是多线程同步的基本手段——保证「主线程不会在子线程跑完前退出」
> ⚠️ **警告**：`std::thread` 对象销毁前必须 `join()`（或 `detach()` 分离），否则程序直接终止——每个线程对象都必须二选一
> 🔄 **知识关联**：`detach()` 分离线程的实例见 [note_17_2 期物示例](./note_17_2_synchronization_primitives.md)；`join()` 与期物 `wait()` 的对比见该笔记知识点6

<a id="id4"></a>
## ✅ 知识点4: 示例：第一个多线程程序

**新线程打印 hello world，主线程 `join()` 等待其结束后再退出。**

**示例/实践**
```cpp
#include <iostream>
#include <thread>

int main() {
    std::thread t([](){
        std::cout << "hello world." << std::endl;
    });
    t.join();
    return 0;
}
```

- 线程 `t` 执行一个 lambda：打印 `hello world.`
- `t.join()`：主线程在此**等待线程 t 结束**（汇合），随后程序退出

**注意点**
> 💡 **理解技巧**：若去掉 `t.join()`，主线程可能先执行到 `return 0`——此时 t 尚未汇合，程序不是「少打印」而是直接异常终止（见知识点3 警告）

## 🔑 核心要点总结

1. **C++11 首次将线程纳入语言标准**：此前只能依赖 `pthread` / Windows API 等平台特定 API，代码难以跨平台移植
2. **`std::thread`（`<thread>` 头文件）是并发编程的基础**：构造时传入可调用目标即创建并启动一个执行线程
3. **两个基本操作**：`get_id()` 获取线程 ID；`join()` 阻塞等待线程结束、与之汇合
4. **线程对象销毁前必须 `join()` 或 `detach()`**，否则程序终止

## 📌 考试速记版

- **头文件**：`<thread>`；**创建**：`std::thread t(可调用目标);`
- **`get_id()`** → 线程 ID；**`join()`** → 等待线程结束（汇合）
- **易混淆**：创建线程 ≠ 等待线程；`join()`（汇合等待）vs `detach()`（分离不管）
- **常见陷阱**：忘记 `join()`/`detach()` → 线程对象销毁时程序终止

**记忆口诀**：`thread` 一造就分叉，`join` 汇合才回家；不 join 不 detach，程序直接垮。
